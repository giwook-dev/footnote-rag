# ADR 0005: 조직 격리는 애플리케이션 계층에서 (RLS는 후속 과제)

- 상태: 채택
- 날짜: 2026-11-24

## 결정

JWT의 `org_id`가 아니라 **DB에서 다시 읽은 사용자**의 `org_id`로 모든 쿼리를 제한합니다(토큰의 `org_id`와 다르면 401). 다른 조직 리소스는 404로 숨깁니다. 벡터 검색은 `chunks.org_id`와 `documents.org_id`를 모두 조건으로 겁니다. 테스트가 문서·답변·작업·검토·검색에서 교차 조직 접근이 404임을 확인합니다.

## 대안: Postgres Row-Level Security

RLS는 쿼리 실수에도 격리를 보장하는 두 번째 방어선이지만, 요청마다 `SET LOCAL app.org_id`를 걸어야 하고, 워커처럼 여러 조직을 처리하는 경로에는 별도 역할이 필요하며, 커넥션 풀과 함께 쓸 때 설정 누수를 조심해야 합니다. 이번 범위에서는 애플리케이션 계층 필터와 테스트로 충분하다고 보고, 다중 테넌트 운영 단계에서 RLS를 추가하는 것을 후속 과제로 둡니다.
