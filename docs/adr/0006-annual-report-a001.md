# ADR 0006: 상장사는 사업보고서(A001)를 기본 대상으로, 주석은 주석 번호별 하위 목차로

- 상태: 채택
- 날짜: 2026-11-24
- 관련: [ADR 0004](0004-opendart-xml-over-pdf.md)의 `list.json` 조회 조건과 주석 제목 규칙을 고칩니다.

## 맥락

실제 `OPENDART_API_KEY`로 확인한 결과(2026-11-24):

- 삼성전자·NAVER·현대자동차 모두 F001(감사보고서)·F002(연결감사보고서) 조회 결과가 0건이었습니다. 상장사는 감사받은 재무제표·주석·감사의견을 정기공시인 **사업보고서**(`pblntf_ty=A`, `pblntf_detail_ty=A001`)에 넣어 공시합니다.
- 삼성전자 사업보고서(`20260310002820`)를 기존 파서로 파싱하면 46개 섹션으로 나뉘지만, `III. 재무에 관한 사항 > 3. 연결재무제표 주석`(약 156,000자)과 `> 5. 재무제표 주석`(약 135,000자)이 통째로 한 섹션이었습니다. 원문에서는 주석 번호마다 `TABLE-GROUP` 안에 `<TITLE ATOC="Y">1. 일반적 사항 (연결)</TITLE>` 같은 소제목이 있는데, 기존 파서는 섹션의 첫 `TITLE`만 경로로 쓰고 주석 안에서는 짧은 번호 `P` 문단만 승격했습니다.

## 결정

1. **보고서 종류 기본값은 A001(사업보고서)입니다.** 허용 코드는 A001, F001, F002입니다. `HttpDartClient.list_reports`는 `pblntf_ty`를 종류 코드의 첫 글자로 정합니다(A001 → `A`, F001/F002 → `F`). `DartClient` Protocol, `find_reports`, `GET /dart/reports`, `cli dart-find`, 웹 화면이 같은 기본값을 씁니다. F001/F002는 비상장사 감사보고서용으로 남깁니다.
2. **주석 섹션(제목에 "주석")의 추가 `TITLE`은 주석 소제목입니다.** 섹션 자신의 첫 `TITLE` 이후에 나오는 `TITLE`마다 새 하위 목차를 시작합니다(`… > 3. 연결재무제표 주석 > 1. 일반적 사항 (연결)`). `TITLE`을 직접 자식으로 가진 컨테이너(`TABLE-GROUP`)는 펼쳐서 같은 규칙을 적용합니다. 소제목 텍스트는 본문에 넣지 않고, 첫 소제목 앞의 본문은 주석 섹션 경로에 둡니다.
3. 기존의 짧은 번호 `P` 문단 승격은 **그 주석 섹션에 `TITLE` 소제목이 하나도 없을 때만** 씁니다. 두 규칙이 섞여 이중으로 승격되지 않게 하기 위해서입니다. "가.", "나." 수준은 나누지 않습니다.
4. 이미 가져온 문서는 **재처리**로 새 파서를 적용합니다: `POST /documents/{document_id}/reprocess`(admin), `cli dart-reprocess`, 웹 화면의 "다시 처리" 버튼. 문서를 `queued`로 돌리고 새 작업을 같은 트랜잭션에서 등록합니다. 수집 핸들러는 청크를 지우고 다시 넣으므로 중복이 생기지 않고, 원문 ZIP 캐시를 재사용합니다.

## 근거

- 상장사 세 곳이 F001/F002로는 아무 문서도 나오지 않으므로, 기본값을 F001로 두면 첫 검색부터 빈 결과가 됩니다.
- 사업보고서에는 감사보고서에 있는 재무제표·주석이 같은 형식으로 들어 있어, 각주 목차 경로(`… 주석 > 16. 우발부채와 약정사항 (연결)`)를 그대로 만들 수 있습니다.
- 주석을 번호별로 나누면 삼성전자 기준 연결 주석 34개, 별도 주석 32개 하위 목차가 생겨, 각주가 "주석 전체"가 아니라 해당 주석을 가리킵니다.

## 대안

| 대안 | 기각 이유 |
| --- | --- |
| F001 기본 유지, 사용자가 A001을 고르게 함 | 상장사 기본 검색이 0건이라 시연 첫 단계부터 막힘 |
| 사업보고서의 첨부 감사보고서 XML(`_00760.xml` 등)을 본문 대신 파싱 | 첨부 처리 정책 변경은 범위 밖. 본문에 재무제표·주석이 이미 있음 |
| 주석 `TABLE-GROUP`의 `ACLASS`(XBRL 코드)로 주석을 식별 | 제목이 이미 `TITLE`에 있고, 코드 체계에 의존하면 회사·연도별 차이에 취약 |

## 한계

- 사업보고서에는 임원 현황 같은 재무 외 섹션도 들어 있습니다. 검색에서 제외하는 필터는 범위 밖입니다.
- 주석 안의 "가./나." 수준 세분화와 표의 셀 단위 구조화는 하지 않았습니다.
- 실제 원문 확인은 삼성전자 사업보고서 한 건으로 했습니다. NAVER·현대자동차 사업보고서는 접수번호만 확인했습니다.
